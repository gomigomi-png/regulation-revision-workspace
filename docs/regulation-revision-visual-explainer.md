# 規程改正ワークスペース 図解

この図解は、`regulation-revision-workspace-notes.md` で固めた初回版の方針を、画面・データ・出力の流れとして整理したもの。

## 1. 全体像

初回版では、外部AIによる自動解析やWord自動読み込みは行わない。
人間が規程本文を貼り付け、アプリが条文候補へ分割し、人間が新文を編集する。

```mermaid
flowchart LR
  A["Word本文をコピー"] --> B["アプリに貼り付け"]
  B --> C["第○条を目印に<br/>条文候補へ分割"]
  C --> D["人間がタイトル・本文を確認"]
  D --> E["Pane 3で新文を編集"]
  E --> F["Pane 4で赤字下線差分を確認"]
  F --> G["新旧対照表Wordを出力"]
  F --> H["改正後全文テキストをコピー"]
  F --> I["修正条文一覧を確認"]

  J["外部AIへ規程本文を送信しない"] -. 初回版ではしない .- E
  K["Wordファイル自動解析"] -. 初回版ではしない .- B
```

## 2. 4ペインの役割

作業の中心は、Pane 3 の新文編集と Pane 4 の赤字下線差分プレビュー。
Pane 1 と Pane 2 は、対象規程と条文を選ぶためのナビゲーションとして使う。

```mermaid
flowchart LR
  subgraph P1["Pane 1: 対象規程リスト"]
    P1A["規程名"]
    P1B["進捗<br/>未着手・編集中・確認済み"]
  end

  subgraph P2["Pane 2: 全条文リスト"]
    P2A["全条文を表示"]
    P2B["修正対象<br/>人間が指定"]
    P2C["差分あり<br/>アプリが検出"]
  end

  subgraph P3["Pane 3: 条文編集"]
    P3A["旧文<br/>固定表示"]
    P3B["新文<br/>編集可能"]
    P3C["修正理由<br/>編集可能"]
  end

  subgraph P4["Pane 4: 差分プレビュー"]
    P4A["選択中条文の<br/>赤字下線差分"]
    P4B["補助候補<br/>履歴・チェック・新旧対照表プレビュー"]
  end

  P1 --> P2 --> P3 --> P4
```

## 3. 条文データの考え方

条文は、旧文と新文を分けて持つ。
旧文は正本として固定し、新文だけを編集することで、新旧対照表と差分プレビューを安定して作れるようにする。

```mermaid
classDiagram
  class RevisionWorkspace {
    +改正案件名
    +対象規程一覧
  }

  class Regulation {
    +規程タイトル
    +進捗ステータス
    +条文一覧
  }

  class Article {
    +条番号
    +見出し
    +旧文
    +新文
    +修正理由
    +修正対象
    +差分あり
    +状態
  }

  RevisionWorkspace "1" --> "複数" Regulation
  Regulation "1" --> "複数" Article
```

## 4. 「修正対象」と「差分あり」の違い

`修正対象` は人間が付ける予定管理の印。
`差分あり` はアプリが旧文と新文の違いから検出する状態。

```mermaid
flowchart TB
  A["条文"] --> B{"人間が<br/>今回直す予定にしたか"}
  B -- はい --> C["修正対象"]
  B -- いいえ --> D["修正対象ではない"]

  A --> E{"旧文と新文が<br/>違うか"}
  E -- はい --> F["差分あり"]
  E -- いいえ --> G["差分なし"]

  C --> H["これから直す予定の条文として管理"]
  F --> I["実際に変更が発生している条文として確認"]
```

## 5. 通常修正・削除・新設の扱い

条文削除や新設でも、旧文と新文の関係を保つ。
条番号の繰り上げや新設番号の調整は、初回版ではアプリが自動で振り直さず、人間が新文側で編集する。

```mermaid
flowchart LR
  subgraph Normal["通常修正"]
    N1["旧文あり"] --> N2["新文あり"]
    N2 --> N3["旧文との差分を表示"]
  end

  subgraph Delete["条文削除"]
    D1["旧文あり"] --> D2["新文なし<br/>または削除状態"]
    D2 --> D3["新旧対照表では<br/>旧あり・新なし"]
  end

  subgraph Add["条文新設"]
    A1["旧文なし"] --> A2["新文あり"]
    A2 --> A3["新旧対照表では<br/>旧なし・新あり"]
  end
```

## 6. 出力の優先順位

初回版の正式なWord出力は、新旧対照表を優先する。
赤字下線入り改正規程全文は最終的に必要だが、初回版では完全自動生成ではなく、人間がWordで作りやすい補助を用意する。

```mermaid
flowchart TB
  A["条文データ<br/>旧文・新文・修正理由・状態"] --> B["新旧対照表Word"]
  A --> C["改正後全文テキスト"]
  A --> D["修正条文一覧"]
  A --> E["条文別赤字下線プレビュー"]

  B --> B1["常務会提出用<br/>左: 新 / 右: 旧"]
  B --> B2["見出しは<br/>修正対象規程のタイトル"]
  B --> B3["修正理由は<br/>提出用には出さない"]

  C --> F["人間がWordへ貼り付け"]
  D --> F
  E --> F
  F --> G["赤字下線入り改正規程全文を作成"]
```

## 7. 初回版でやらないこと

```mermaid
mindmap
  root((初回版でやらないこと))
    Wordファイル自動読み込み
      書式や表の揺れが大きい
    対象規程・対象条文の自動抽出
      規程マスタと法務判断が必要
    外部AIによる本文解析
      社内規程を外部に出さない
    赤字下線入り全文Wordの完全自動生成
      初回版は人間の作業補助を優先
    共同編集・承認ワークフロー
      将来機能として残す
```

## 8. まず作るべき初回操作フロー

```mermaid
flowchart TD
  A["対象規程を追加"] --> B["規程全文を貼り付け"]
  B --> C["条文候補を生成"]
  C --> D["条文を選択"]
  D --> E["修正対象にする"]
  E --> F["新文を編集"]
  F --> G["修正理由を書く"]
  G --> H["赤字下線差分を確認"]
  H --> I{"問題なし?"}
  I -- いいえ --> F
  I -- はい --> J["新旧対照表Wordを出力"]
  J --> K["改正後全文テキスト・修正条文一覧で<br/>赤字下線入り全文作成を補助"]
```
